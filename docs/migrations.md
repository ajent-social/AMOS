# Database migrations

AMOS stores applied migration IDs and SHA-256 checksums in `amos_schema_migrations`. Startup or an explicit maintenance command constructs the application `storage.DB` with `storage.Open(ctx, postgresURL)` and passes the assembled `migrations.Registry` to `storage.Migrate(ctx, db, registry)`. `Open` validates the URL and pings PostgreSQL with the caller's context; URL and credential data are never included in its errors. The owning application closes the handle during shutdown.

Domain owners contribute SQL in a `migrations.Fragment` under their namespace. The integrator assigns each migration a global sequence starting at 1 with no gaps, assembles the fragments using `migrations.NewRegistry`, and owns the combined registry. Migration IDs are the stable `sequence.namespace.name` tuple; never rename or reuse an applied ID. The checksum is SHA-256 over the exact SQL source bytes, including whitespace and comments, so any edit to an applied migration is rejected before new work begins.

Each migration is run in its own PostgreSQL transaction. A transaction-level advisory lock serializes migrators across processes; the migration SQL and its ledger row commit together. Ledger triggers reject row updates, deletes, and truncation so applied IDs and checksums remain append-only. Re-running the same registry is idempotent. The applied ledger must be a contiguous prefix of the registry. A shorter, reordered, renamed, or checksum-changed registry fails without changing domain data. Failed SQL rolls back its DDL/DML and ledger insertion. Keep migration scripts transactional and free of external side effects.

Migrations are forward-only. Do not write automatic `down` scripts or delete/alter ledger entries. Use expand/contract changes that allow the previous and new application versions to coexist. Destructive cleanup, data loss, or external effects require a separate owner-approved migration and recovery plan; recovery uses a forward repair or a verified backup restore. Production execution and backup/restore qualification are integration gates, not claims established by local tests.
