# Email delivery contract (v1)

AMOS email delivery creates a durable `email.send.v1` external-effect job in the caller's SQL transaction. Its payload contains only the allowlisted template name, an opaque reference in the exact `material:<canonical-lowercase-UUIDv7>` form, and a bounded expiry. Email addresses, provider paths, URLs, and other arbitrary strings are rejected as references. A configured privileged `MaterialResolver` resolves the identifier immediately before sending into ephemeral recipient/action-URL material. If that resolver is absent, construction fails with setup-required; if a reference cannot be resolved, no provider call occurs and the job may be safely retried.

Recipient addresses and action URLs are private owner data. They must remain in the owner-controlled secret/material store with an explicit bounded retention policy, and must never enter job payloads, logs, diagnostics, or upstream issue reports. The resolver owns secure storage, access control, revocation, and retention. This package provides no encryption implementation and does not claim that database-at-rest encryption protects plaintext material from database readers. Resolver implementations must return unavailable until an owner-qualified protected store is configured.

The renderer accepts only the three built-in templates (`sign_in`, `verify_email`, `reset_password`), a single valid recipient, and a same-origin HTTPS action URL with no user information or fragment. Subjects are fixed, both text and HTML are rendered with safe template engines, and body size and link expiry are bounded. Template data is not caller-authored HTML.

`EmailSender.Send` returns a sealed receipt. `Accepted` means the provider accepted a message for processing; it does not mean the recipient received or read it. `Rejected` means a definite provider rejection. A transport failure, provider 5xx, missing provider message ID, or otherwise ambiguous result is `Unknown`. Unknown outcomes must be reconciled using a verified provider event matched to the job ID; an absent, unverified, or mismatched event remains unknown/manual review and must never be treated as proof that retrying is safe. There is no exactly-once delivery claim.

The SES adapter uses AWS SDK for Go v2 SES v2, one recipient per request, a required explicit region, credential reference, sender address, and configuration set. It disables SDK retries so an ambiguous send is not silently repeated. Credentials are resolved through an explicit owner-provided resolver; there is no anonymous or default-credential fallback. Raw SDK errors and request bodies are not exposed in public errors or logs.

SES credentials, sender/domain verification, configuration-set event destinations, verified event ingestion, and a qualified owner mailbox remain deployment/provider gates. No production SES send or recipient-delivery qualification is claimed by this contract.
