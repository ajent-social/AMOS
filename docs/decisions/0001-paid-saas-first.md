# Decision 0001: launch a new paid SaaS application first

Date: 2026-09-29. Status: accepted product priority.

## Decision

The founder selected "Launch a new paid SaaS app" when asked which first-release outcome should lead AMOS. This takes priority over the earlier recommendation to begin with an existing-app upgrade.

## Consequences

The first reference path must connect authentication, subscription checkout, verified entitlement enforcement and a useful paid application feature. Delivery and recovery evidence belong in the proposed release criteria. Basic subscription billing moves into that reference path; advanced usage billing and autonomous infrastructure operations need not precede it.

Existing-app adoption remains a subsequent proof of reuse. Individual training scopes and agendas remain independent of the platform release plan.

## Boundaries

This decision chooses the outcome, not a final architecture, product domain, provider, license or release date. It does not authorize spending or deployment. Detailed implementation proposals remain in [the brainstorming note](../brainstorm-2026-09-29.md).
