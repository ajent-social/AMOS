# Private callback database guard (v1.18)

Status: proposed; freezes after independent exact-head review and merge.

The private callback database factory has the package-private shape:

```go
func newCallbackDB(tx *sql.Tx) (DBTX, func() error, error)
```

Guard-owned sentinels are private: errCallbackClosed, errCallbackBusy, errCallbackUnfinished, errCallbackCleanup, errCallbackSQL and errCallbackContext. Nil transactions reuse errNilSQLTx; no new exported error vocabulary is introduced.

It rejects nil transactions, wraps exactly the supplied transaction through the private result adapter, and returns a separate owner-only invalidation closure. The callback-facing concrete value has only the three DBTX methods. It has no embedded transaction, exported field, transaction getter, lifecycle method, pool, fallback, retry, or constructor accessible to business packages. Row and Rows values are private wrappers sharing the same lifetime state. Factory construction cannot prove that the supplied transaction is still active; completed transactions fail through the ordinary database transaction error.

### Lifetime and concurrent use

The callback must finish each SQL request and consume or close each result before returning. One transaction lease is admitted at a time: Exec owns it until completion, Query owns it until Rows close or exhaustion, and QueryRow owns it until its first Scan finishes. A competing DBTX request fails immediately with a private busy sentinel, even when the existing rows are idle. No queued request waits behind an unconsumed result. Calls on one result are likewise serialized by fail-fast admission; concurrent use returns busy (Next returns false and exposes busy through Err). Callback code must not concurrently iterate one result; race-safe rejection is promised, meaningful concurrent iteration is not. Busy rejection does not cancel the admitted request or release its lease.

Invalidation first marks the shared state closed under a short mutex. No later call is admitted. It cancels any unfinished request, waits for an already admitted method to leave, closes any tracked result, releases its per-request cancellation resources, and returns only after drain. It never holds the lifetime mutex while calling driver methods, context cancellation callbacks, Scanner callbacks, Rows.Close, or waiting for drain. Repeated/concurrent invalidation joins the same completion and returns the same result. A normal owner cannot reuse, commit, or roll back the real transaction concurrently with wrapper use; it must wait for invalidation. Wrapper cleanup itself never commits or rolls back.

Any request or result lease still outstanding at invalidation marks cleanup with a private unfinished-work sentinel, even if cleanup succeeds. A close failure marks cleanup with a private cleanup sentinel; raw SQL or driver diagnostics are not added by the guard. The future owner must roll back when invalidation fails and must not encode, audit success, or commit. Callback failure and cleanup failure remain inspectable with errors.Is; panic cleanup must preserve the exact original panic. This rule prevents an escaped goroutine's partial work from silently becoming a successful invocation.

A method admitted before invalidation may finish during drain, including writes to caller Scan destinations; invalidation is not retroactive erasure. After invalidation completes, no driver call or destination mutation remains outstanding. Already copied results and sql.Result metadata are not revoked. All later DBTX calls fail closed: Exec returns nil/error, Query returns a genuinely nil Rows/error, and QueryRow returns an error Row whose Scan reports the closed sentinel. Retained Row.Scan and Rows.Scan/Err/Close return the closed sentinel; retained Rows.Next returns false and Err reports closed, including previously exhausted/closed handles. Cleanup is nevertheless performed exactly once. Before invalidation, normal Rows.Close is idempotent and exhausted Rows.Err preserves its terminal error; an already consumed Row reports sql.ErrNoRows on a second Scan. Closed-state errors take precedence over old query errors, busy state and caller context errors after closure.

Each admitted SQL call derives a cancelable context from its supplied context; nil contexts fail without driver access. Its cancel function stays attached to the lease until result completion. QueryRow eagerly issues QueryContext, records errors for Scan, reads/scans only its first row and closes the remainder; it preserves sql.ErrNoRows and rejects *sql.RawBytes as database/sql.Row does. Error Row values expose only Scan and no underlying result. Rows Scan data obeys database/sql's ordinary ownership rules. Cancellation/SQL/deadlock errors from admitted calls are preserved internally and do not cause automatic retry. The future owner maps errors for public transport and rolls back unusable transactions.

There is no universal bounded-drain promise for a driver or user Scanner that ignores cancellation. The supported driver must pass bounded real-database cancellation tests. Trusted callback code must use bounded contexts and return from Scanner implementations. No cleanup goroutine is abandoned to make a timeout appear successful; owner transaction reuse remains prohibited until actual drain. A blocked driver/Scanner is an operational failure, not evidence of successful invalidation.

The future integration must invalidate immediately when the handler returns or panics, before result-kind checking, output encoding or output validation. Wrapping the complete current Definition.invoke call is insufficient because it includes codec work. The private factory slice does not itself install that handler boundary or enable dispatch.

### Finite SQL admission profile

Apply the same validator before every ExecContext, QueryContext and QueryRowContext driver call. Accept exactly one statement whose first significant token is an unquoted ASCII SELECT, INSERT, UPDATE or DELETE, case-insensitively. Leading comments/ASCII whitespace are allowed. Reject every other leading token, including WITH, VALUES, MERGE, EXPLAIN, CALL, DO, PREPARE, EXECUTE, COPY, SET, RESET, DISCARD and all transaction-control commands. This is deliberately narrower than PostgreSQL SQL; unsupported syntax returns a private unsupported-SQL sentinel without driver access. It is not a SQL correctness parser.

Use an iterative byte scanner, not regex stripping or strings.Fields. SQL text must be 1..65536 bytes and ASCII; NUL, DEL and controls other than space/tab/LF/CR/form-feed are rejected. Unicode identifiers, literals and whitespace in SQL text are rejected explicitly; Unicode data remains supported through parameters. Do not normalize Unicode or fold it into ASCII. Reject backslash anywhere in SQL text, including quoted text/comments, to eliminate server string-mode ambiguity in this profile.

Scanner states are ordinary text, single-quoted string, double-quoted identifier, line comment and nested block comment. Quotes escape only by doubling the same quote. Semicolons/comment markers inside quotes are data; quotes/semicolons inside comments are ignored. Line comments run to CR/LF or end of input. Block comments nest to at most 32; unfinished comments or quotes fail. Ordinary parentheses must balance with depth at most 64; semicolon at nonzero depth fails. Allow at most one ordinary semicolon at depth zero and only as an optional final terminator: after it only whitespace/comments are permitted. Reject leading empty statements, repeated terminators and any subsequent significant token.

Unquoted identifier tokens use ASCII letters/underscore followed by ASCII letters/digits/underscore. Outside quotes and comments, dollar signs are admitted only as a standalone parameter token `$` followed by a nonzero decimal integer, with no leading zero and a non-identifier boundary on both sides. Reject dollar-quoted strings, dollar-containing identifiers and malformed parameter tokens. Reject prefixed E/B/X/N strings, U& string/identifier forms, and the unquoted UESCAPE keyword; these forms are outside this profile even when harmless. Recognize these forms before treating quotes independently. Ordinary non-quote punctuation/operators and numeric text need not be semantically parsed; PostgreSQL retains syntax/type validation. All query/argument bytes pass through unchanged after validation.

Consequently BEGIN [WORK|TRANSACTION], START TRANSACTION, COMMIT/END [WORK|TRANSACTION] [AND [NO] CHAIN], ROLLBACK/ABORT variants, ROLLBACK TO [SAVEPOINT], SAVEPOINT, RELEASE [SAVEPOINT], PREPARE TRANSACTION, COMMIT PREPARED, ROLLBACK PREPARED, SET [LOCAL|SESSION] TRANSACTION and SET SESSION CHARACTERISTICS AS TRANSACTION are rejected by the positive first-token rule, including mixed case and comment-separated variants. No expanding denylist is the security boundary. Quoted occurrences such as SELECT 'COMMIT; ROLLBACK' remain data and are allowed within the profile.

Handlers remain trusted owner-reviewed application code. This restriction prevents accidental direct transaction lifecycle statements; it does not sandbox SQL, authorize rows, stop functions/triggers with side effects, constrain SELECT INTO or calls such as set_config, prevent other process capabilities, or qualify a production database role. Least-privilege roles, complete lock sets and current authority remain separate required gates.


## Required evidence

1. Factory/method shape: nil rejected; exactly DBTX methods; no embedded/exported tx; Row/Rows cannot assert to raw *sql.Row/*sql.Rows; no Commit/Rollback/Begin/Unwrap path. Completed tx returns actual transaction error. Query error returns nil interface, Row error deferred to Scan.
2. SQL table tests on all three methods: allow basic parameterized four DML forms, RETURNING, quoted keyword/semicolon/comment text, doubled quotes, nested comments, ASCII whitespace and one trailing terminator/comment. Preserve query/args and Unicode parameter values exactly.
3. Rejection table: all variants enumerated above, leading comment variants, SELECT 1; COMMIT, SELECT 1;;, leading semicolon, unclosed quote/comment, nested block depth33, parentheses depth65/unbalanced, semicolon inside parentheses, dollar quotes with empty/named/Unicode tags, $0/$01/$1name, U&/UESCAPE/E/B/X/N forms, backslash quote attacks under either string mode, BOM/NBSP/zero-width/non-ASCII text, NUL/DEL, empty/comment-only/oversized strings. Assert zero driver calls on every rejection and no panic/hang.
4. Scanner fuzzing with bounded input: deterministic termination, no panic; seed all quote/comment/dollar/semicolon boundaries. Accepted text must have exactly one scanner statement and permitted first token. This invariant is not a parser or security proof; real-server tests remain necessary.
5. Lifetime: retain DBTX, unscanned Row, active Rows, exhausted Rows, already closed Rows; invalidate and exercise every method. Closed sentinel precedence and nil interfaces; exactly one underlying close; no new driver calls; unchanged Scan destination for calls begun after closure.
6. Lease behavior: concurrent Exec/Query/QueryRow; unread result then second query; concurrent Next/Scan/Close; scanner re-enters DBTX and receives busy without deadlock; cancellation releases lease; double/concurrent invalidation returns same error. Channel barriers force query completion racing close and Next/Scan racing invalidation. Run normal and race checks.
7. Drain: unfinished Exec, abandoned Row, partially read Rows, context cancellation, close failure, scanner blocking then released. Prove invalidation cannot return before the admitted method drains, never holds its mutex over I/O/callbacks, and unfinished work requires rollback. No bounded-return claim for an uncooperative fake driver.
8. Real TLS PostgreSQL in an assigned serial fixture window: same transaction ID and uncommitted visibility; completed DML then invalidate then owner commit succeeds; unfinished result invalidation forces owner rollback; all retained methods fail. Attempt each direct control form through all three APIs and show the transaction stays usable and later owner rollback undoes its writes. Required fixture absence must fail, not skip.
9. Real cancellation: bounded pg_sleep query, invalidation cancellation/drain, sql.ErrNoRows, query error, partially iterated close. Real two-transaction opposite-row-lock deadlock test on exact-owned fixture rows must observe SQLSTATE40P01 on one participant and no automatic replay; release both transactions and cleanup exact owned rows. Use two sessions only and explicit test deadline; driver double is insufficient for PostgreSQL deadlock semantics.
10. Independent negative/restored evidence: bypass closed check for retained Row.Scan and show the new regression fails; separately bypass SQL validator and show transaction-control/no-driver-call test fails; restore exact bytes and rerun. Different reviewer owns acceptance.

remain unchanged. Source factory tests do not qualify future handler-boundary
