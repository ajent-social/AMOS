# Password-change completion policy proposal

Status: proposed finite extension for B1; different-author design review is required before source adoption. This is not current host admission or full policy qualification.

A successful native password change intentionally advances the person's security epoch exactly once and revokes every unrevoked session, including the admitted actor session. Reusing the ordinary `AuthorizePasswordChange` at F with the original principal incorrectly compares the old epoch to the intentional new epoch. Minting a new principal would incorrectly imply a new current session.

The W1 recovery constructor requires a policy implementing the existing reset/change policy plus `AuthorizePasswordChangeCompletion(context.Context, *sql.Tx, identity.Principal, int64) error`. The arguments are the unchanged privately refreshed actor principal captured before mutation and the exact epoch returned by the journaled epoch update. The native writer independently verifies new epoch equals original epoch plus one and rechecks the complete expected credential/contact/person tuple and all session revocations at the original F. It invokes completion policy using the same lexical transaction and original root context after F, with plain reads only: no locks, mutations, clock sampling, or authority creation.

The supported local implementation checks the original principal's realm, person and epoch, requires the supplied new epoch to equal original epoch plus one without overflow, reads the active current person at exactly that new epoch, and re-evaluates the same local password-change policy predicates. The existing local change policy delegates its business predicates to the same personal workspace / no organization membership / no enterprise binding helper; completion uses that helper after its explicit transition check. This shared predicate is an implementation detail, not a substitution of reset authorization for change authorization. Assurance-aware future policies must enforce their own unchanged change predicates on the original refreshed principal; the final native actor proof checks its original liveness bounds at F.

This method does not authorize a write, prove a live post-change session, issue a credential, or produce a principal. It only denies or permits completion of the already-authorized, exactly verified transition. An implementation that lacks this explicit method is rejected by the W1 constructor; legacy constructors retain their existing policy interface and behavior. The fixed composition and exact implementation still require independent source/runtime review; arbitrary callbacks are not qualified by this interface.

Required tests include successful exact epoch-plus-one and all-session revocation; mismatched old/new epoch; canceled original root; final policy failure rolling back password, epoch and revocations; expired/downgraded actor; and no response release on rollback or failed commit.
