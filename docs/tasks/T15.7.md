## Objective

Prevent coding agents from modifying the controls that judge or release their own changes.

## Implementation instructions

1. Define protected policy/tests/workflow/release identity paths and indirect control surfaces such as generators, test runners, build hooks and dependency scripts.
2. Evaluate exact candidate changes plus transitive execution-impact indicators against independently stored rules.
3. Classify unknown/security/identity/billing/destructive migration effects as elevated review and prohibit self-approval.
4. Test direct, renamed, generated, dependency-based and symlinked control mutations with immutable policy fixtures.

## Acceptance criteria

- No candidate can approve its own policy or change protected acceptance/release authority automatically.
- Ambiguous indirect control changes hold for elevated review.
- Scoped checks, formatting and configured lint pass; E16 separately records any required deployed/live verification before this behavior is advertised.

Use cases: UC-098, UC-114, UC-116, UC-117.

## Negative verification

Patch a build script to delete mandatory tests before execution; evaluator must classify it as protected-control change.

For behavior changes, show the check detects the predicted failure using a disposable isolated test mutation, then restore and report the passing check. Never damage a shared checkout or live environment. A design-only task uses a rejected schema/document fixture instead of pretending it changes runtime behavior.
