## Implementation instructions

1. Add fuzz targets for OpenAPI extension decoding, tool inputs, proxy paths/headers, identity envelope parsing and diagnostic decoding.
2. Seed encoded traversal, duplicate keys, nested/huge schemas, invalid UTF-8, decompression and integer-overflow cases.
3. Assert bounded allocation/work, no panic, canonical security decision and no accepted ambiguity.
4. Record reproducible crashes as fixtures and cap fuzz duration/concurrency under shared build discipline.

## Acceptance criteria

- Seed corpus passes deterministic negative assertions and fuzz targets cannot bypass policy through alternate encoding.
- Any discovered crash has a minimized reproducible fixture before the task closes.
- Scoped checks, formatting and configured lint pass; E16 separately records any required deployed/live verification before this behavior is advertised.

Use cases: UC-091, UC-095, UC-105, UC-117.

## Negative verification

Duplicate conflicting tenant/policy keys in a payload; parser rejects ambiguity rather than honoring the attacker-selected occurrence.

For behavior changes, show the check detects the predicted failure using a disposable isolated test mutation, then restore and report the passing check. Never damage a shared checkout or live environment. A design-only task uses a rejected schema/document fixture instead of pretending it changes runtime behavior.
