## Implementation instructions

1. Create reproduction bundles using public releases, synthetic configuration/data and minimal scripted behavior.
2. Exclude private source/logs/names/domains/paths and provenance-restricted excerpts; review derived examples for copied identifying structure.
3. Execute bundles in a clean isolated environment without owner credentials and bind inputs/results by digest.
4. Quarantine bundles that require inaccessible evidence or cannot reproduce; do not fabricate a public defect from a private assertion.

## Acceptance criteria

- Accepted bundle reproduces a public shared-code failure using only public inputs and synthetic data.
- Publication scan and schema tests reject business source or identifying path content.
- Scoped checks, formatting and configured lint pass; E16 separately records any required deployed/live verification before this behavior is advertised.

Use cases: UC-106, UC-108, UC-109, UC-117.

## Negative verification

Bundle imports a private module or requires an owner secret; qualification must fail before publication.

For behavior changes, show the check detects the predicted failure using a disposable isolated test mutation, then restore and report the passing check. Never damage a shared checkout or live environment. A design-only task uses a rejected schema/document fixture instead of pretending it changes runtime behavior.
