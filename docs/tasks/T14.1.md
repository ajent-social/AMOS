# T14.1: Freeze public diagnostic schema and privacy budget

Status: PLANNED. Detailed draft, not execution-certified. Stage S4; wave 14; owning lane L16; estimate 90 minutes (planning hypothesis).

## Objective

Define an allowlist that makes private information structurally ineligible for default export.

## Dependencies and readiness

T1.2, T10.1, T10.3

Read the actual outputs of every dependency before starting. Reconcile this contract against the frozen contract version and current code; report material mismatch instead of inventing behavior. The listed verification commands are future prescriptions, not claims that executables already exist.

External gate: None beyond normal task authorization and prerequisites.

## Scope

- api/schemas/upstream-diagnostic.schema.json
- docs/contracts/upstream-diagnostics.md
- internal/diagnosticcontract/*

Only these owned paths may change. Repository-qualified upstream paths require a separate upstream task claim and that repository's permissions/review rules; they are not permission to edit a neighboring checkout. Shared module files, migration ordering, aggregate APIs, root workflow wiring and executable entrypoints remain integrator-owned unless explicitly listed and exclusively delegated.

## Implementation instructions

1. Specify bounded public component versions, aggregate metrics, approved error codes and stable public error signatures.
2. Restrict stack representation to allowlisted public AMOS/AMSL frames; strip home/build/source paths, business symbols, addresses, URLs, identifiers and argument values.
3. Define payload/count/rate/retention bounds, owner inspection/disablement and schema evolution rules; document residual fingerprinting risks.
4. Add schema fixtures rejecting arbitrary string maps, raw message/log fields and nested unknown properties.

## Acceptance criteria

- Schema cannot carry arbitrary raw log/source/metadata fields by default.
- Synthetic secrets, home paths, custom business symbols and infrastructure identifiers are rejected or omitted before serialization.

Use cases: UC-104, UC-105, UC-111, UC-117.

## Negative verification

A stack frame contains an application-specific symbol and home path; exported frame must be absent, not merely regex-redacted.

For behavior changes, show the check detects the predicted failure using a disposable isolated test mutation, then restore and report the passing check. Never damage a shared checkout or live environment. A design-only task uses a rejected schema/document fixture instead of pretending it changes runtime behavior.
