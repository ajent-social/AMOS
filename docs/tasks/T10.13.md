## Implementation instructions

1. Inventory database credentials, session keys, webhook signing secrets, Cloudflare tokens and deployment roles by owner and rotation mechanism.
2. Define dual-key overlap only where the actual provider/module supports it; otherwise require a maintenance procedure.
3. Validate secret references before activation and keep old references until health verifies replacement.
4. Record audit-safe rotation metadata and rollback limits without writing secret values.
5. Implement the named verification cases at the real changed boundary; run the specified negative case in a disposable fixture, observe its predicted failure, restore the behavior, and record both results.

## Acceptance criteria

- A failed credential probe prevents replacing the active secret reference.
- Cloudflare and AWS provisioning credentials are not exposed to app runtime.
- Named scoped checks pass and the specified negative case is demonstrated; live/production qualification remains a separate explicitly authorized E16 gate where applicable.
