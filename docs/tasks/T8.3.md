## Implementation instructions

1. Generate an S3 backend bucket specification with encryption, versioning, public-access block and narrow IAM.
2. Define the KMS secret-provider key and recovery grants independently of the application stack.
3. Use a local bootstrap state only for the initial state foundation, then document and validate migration to the S3 backend.
4. Protect state resources from application teardown and expose no raw state or decrypted secrets in logs.
5. Implement the named verification cases at the real changed boundary; run the specified negative case in a disposable fixture, observe its predicted failure, restore the behavior, and record both results.

## Acceptance criteria

- Application destroy cannot delete its own state bucket or recovery key.
- Two writers use Pulumi backend locking; stale-lock recovery is documented and manual.
- Named scoped checks pass and the specified negative case is demonstrated; live/production qualification remains a separate explicitly authorized E16 gate where applicable.
