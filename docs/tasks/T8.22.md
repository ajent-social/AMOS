## Implementation instructions

1. Wire reviewed provider pins and managed compute/database/edge resources into self-hosted Pulumi state.
2. Implement common typed outputs for target, database secret reference, health origin, artifact and recovery handles.
3. Use immutable task-definition digest and explicit deployment failure/rollback settings; run migrations through the frozen one-off task boundary.
4. Test failed migration, unhealthy rollout and source/digest mismatch without claiming automatic data rollback.
5. Implement the named verification cases at the real changed boundary; run the specified negative case in a disposable fixture, observe its predicted failure, restore the behavior, and record both results.

## Acceptance criteria

- Managed profile satisfies the same CLI plan/apply/status envelope as small-vm.
- An unhealthy rollout returns actual active/pending deployment state and nonzero outcome.
- Named scoped checks pass and the specified negative case is demonstrated; live/production qualification remains a separate explicitly authorized E16 gate where applicable.

## Negative verification

Make migration task fail and assert the new application service version is not marked healthy.

For behavior changes, show the check detects the predicted failure using a disposable isolated test mutation, then restore and report the passing check. Never damage a shared checkout or live environment. A design-only task uses a rejected schema/document fixture instead of pretending it changes runtime behavior.
