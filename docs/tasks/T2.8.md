# T2.8: Implement shared operation policy and durable invocation boundary

Status: PLANNED. Execution evidence is recorded below; release acceptance remains separate. Stage S1; wave 12; owning lane L01; estimate 90 minutes (planning hypothesis).

## Objective

One shared typed operation boundary rechecks current authority for new mutations and replay, and prevents duplicate payload-bound writes across transports.

## Implementation instructions

1. Implement the first bounded slice in app/operation/: immutable registry construction and typed descriptor validation against the frozen policy contract types. Do not create app/policy or invent policy vocabulary.
2. Keep worker ownership to app/operation/**. The integrator separately owns policy implementation/adapters, current session recheck, invocation SQL storage, audit API/schema, migration content/sequence/registry, and executable composition.
3. Derive actor kind from trusted Actor.Kind() as a private validated string; the initial profile accepts person only. Callers and operation input cannot select actor, tenant, workspace, authority, or session values.
4. For integrated dispatch, use one executor for web, REST, MCP, and proxy. Recheck current active person/session, selected workspace/membership, complete resource lock set, permission, assurance, and entitlement in the transaction; recheck authority before any replay result is disclosed.
5. For required writes, bind idempotency to trusted realm, actor, workspace, operation, immutable descriptor revision/schema digests, and canonical path/query/body input. Exact authorized replay returns the original typed result; changed input or revision conflicts without rerunning the handler.
6. Commit domain mutation, bounded replay result, success audit, and durable effect intent atomically; never call providers in the transaction. Enforce typed effect payload schema/size/privacy/deadline and unique effect ordinals.
7. Keep replay outputs bounded and replay-safe; sensitive and secret output is not cached. Completed replay records have no implicit expiry or automatic deletion. Exhausted explicit capacity fails unavailable until an operator raises and assigns capacity.
8. Do not enable executor dispatch until root-owned adapters, current-session seam, SQL/audit schema, allocated migration, and every supported executable composition are integrated and independently qualified.

## Acceptance criteria

- Registry tests require immutable input and output codecs with `SchemaDigest() [32]byte`; reject zero metadata/codec digests and independent input/output mismatches before binding, and prove copied metadata isolation and no digest recomputation after binding. Digest equality checks trusted binding consistency, not arbitrary codec correctness.
- Registry tests reject duplicate/incomplete descriptors, schema or transport-binding mismatch, unknown/duplicate input fields, invalid typed codecs, duplicate effect ordinals, and unknown, oversized, or privacy-disallowed effect payloads.
- Real PostgreSQL transaction tests prove exact same-key/hash replay returns the original canonical result once; changed input/revision conflicts without a second callback or false denial audit; scopes isolate installation/application/environment/actor/workspace/operation; concurrent duplicates invoke once; corrupt stored results fail closed.
- Real PostgreSQL tests prove current person/session/workspace/membership/resource/assurance/permission/entitlement state is rechecked before mutation and replay disclosure, with denied versus unavailable preserved; revocation/permission writes serialize with invocation using the documented lock order.
- Real PostgreSQL failure tests prove mutation, replay row/capacity reservation, success audit, and durable effect intent roll back together on callback/output/audit/outbox/commit failure; capacity admission is bounded and exhaustion prevents callback until explicit operator allocation is increased.
- Only after root-owned adapters, audit/schema, allocated migration, and transport composition pass those real-database checks can the executor be enabled. Source-task acceptance remains pending independent review, merge, landed checks, and required real-service evidence; no provider/deployment/release claim follows.

## Negative verification

Use an isolated disposable test mutation to weaken descriptor validation or bypass current authority on replay; prove the scoped check fails, restore the exact source, and rerun the passing check. Real PostgreSQL negative cases must prove changed intent never invokes twice and revoked authority never discloses cached output.

For behavior changes, show the check detects the predicted failure using a disposable isolated test mutation, then restore and report the passing check. Never damage a shared checkout or live environment. A design-only task uses a rejected schema/document fixture instead of pretending it changes runtime behavior.
