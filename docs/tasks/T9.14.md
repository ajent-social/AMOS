## Implementation instructions

1. Generate self-hosted S3 backend login and KMS secret-provider environment wiring without a Pulumi Cloud token.
2. Use separate AWS OIDC trust policies for preview/deploy with exact repository/environment subject and audience.
3. Ensure preview cannot assume a write role; treat any executed IaC code as privileged and exclude untrusted changes.
4. Bind apply to protected environment approval, exact revision/digest/plan, and serialized noncanceling deployment concurrency.
5. Implement the named verification cases at the real changed boundary; run the specified negative case in a disposable fixture, observe its predicted failure, restore the behavior, and record both results.

## Acceptance criteria

- Untrusted events cannot access AWS/Cloudflare/state secrets.
- No generated job runs pulumi up under a preview identity.
- Named scoped checks pass and the specified negative case is demonstrated; live/production qualification remains a separate explicitly authorized E16 gate where applicable.
