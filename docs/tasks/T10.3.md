Status: PLANNED. Detailed draft, not execution-certified. Stage S1; wave 10; owning lane L13; estimate 90 minutes (planning hypothesis).

## Objective

Capture useful request context without credential or personal-data leakage.

## Implementation instructions

1. Emit stable request ID, route template, method, status, duration and sanitized error code.
2. Accept external correlation only through bounded validation and create a safe internal ID otherwise.
3. Redact cookies, authorization, tokens, provider keys, request bodies and sensitive query parameters by allowlist.
4. Test success, panic/error boundary and malformed correlation input against real handlers.
5. Implement the named verification cases at the real changed boundary; run the specified negative case in a disposable fixture, observe its predicted failure, restore the behavior, and record both results.

## Acceptance criteria

- Logs support correlation across app and business service without storing raw bodies.
- Injected credentials never appear in encoded log output.
- Named scoped checks pass and the specified negative case is demonstrated; live/production qualification remains a separate explicitly authorized E16 gate where applicable.

Use cases: UC-073, UC-079.

## Negative verification

Send a bearer token and session cookie through a failed request and assert neither appears in logs.

For behavior changes, show the check detects the predicted failure using a disposable isolated test mutation, then restore and report the passing check. Never damage a shared checkout or live environment. A design-only task uses a rejected schema/document fixture instead of pretending it changes runtime behavior.
