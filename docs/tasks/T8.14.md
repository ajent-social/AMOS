Status: PLANNED. Execution evidence is recorded below; release acceptance remains separate. Stage S2; wave 10; owning lane L10; estimate 90 minutes (planning hypothesis).

## Objective

Make accepted cost and data-retention constraints machine-checkable.

## Implementation instructions

1. Deny public database access, unencrypted disks/state, unscoped IAM and deletion of protected data resources.
2. Validate resources against the selected profile: NAT, ALB and database tier must be explicitly allowed and costed; reject extras or silent profile switching.
3. Require explicit plan acknowledgment for replacements, retained-resource cost and backup retention changes.
4. Keep cost values timestamped estimates and do not represent an estimate as an AWS billing limit.
5. Implement the named verification cases at the real changed boundary; run the specified negative case in a disposable fixture, observe its predicted failure, restore the behavior, and record both results.

## Acceptance criteria

- Policy rejects the enumerated unsafe fixtures before apply.
- Cost notices include resources retained after teardown and variable-cost caveats.
- Named scoped checks pass and the specified negative case is demonstrated; live/production qualification remains a separate explicitly authorized E16 gate where applicable.
