Status: PLANNED. Execution evidence is recorded below; release acceptance remains separate. Stage S5; wave 36; owning lane L15; estimate 90 minutes (planning hypothesis).

Make retries and restart visible state transitions rather than duplicate release side effects.

## Implementation instructions

1. Implement versioned state transitions and unique idempotency keys in the owner job store using root-assigned migration order.
2. Record actor, source/evidence/policy digest, attempt budget and lease ownership with each event.
3. Reconcile expired leases and unknown external effects before retrying; do not turn timeout into confirmed failure.
4. Test concurrent claims, process death after durable transition, duplicate acknowledgment and stale actor writes.

## Acceptance criteria

- Only one worker claims a given job version; stale lease holders cannot publish results.
- Replayed transition events cannot trigger duplicate release actions.
- Qualification fails explicitly when the required real database/restore fixture is unavailable; skipped integration cases are not a pass.
- Scoped checks, formatting and configured lint pass; E16 separately records any required deployed/live verification before this behavior is advertised.

## Negative verification

Crash after release request persistence before acknowledgment; restart must reconcile the same request instead of creating another.

For behavior changes, show the check detects the predicted failure using a disposable isolated test mutation, then restore and report the passing check. Never damage a shared checkout or live environment. A design-only task uses a rejected schema/document fixture instead of pretending it changes runtime behavior.
