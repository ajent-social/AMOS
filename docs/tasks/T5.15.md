## Implementation instructions

1. Persist append-only event identity, workspace, actor/service, meter version, occurrence time, received time and exact nonnegative quantity.
2. Enforce authenticated meter-writer scope and server-bound workspace; reject conflicting duplicate IDs and invalid numeric/period inputs.
3. Use transactional outbox hook for successful billable business operation, defining failed-operation and retry billing semantics.
4. Test exact replay, conflicting replay, rollback, cross-tenant attribution and oversized/negative amounts.
5. Format touched Go files with gofmt and changed frontend files with the pinned formatter; run scoped vet/lint and the named behavioral checks, rejecting skipped or zero matching tests.

## Acceptance criteria

- Same usage identity contributes once; differing payload under same identity conflicts.
- Failed rolled-back business operation cannot create finalized billable usage.

Use cases: UC-044.
