Build bounded issue clusters while preserving uncertainty and privacy of derived data.

## Implementation instructions

1. Deduplicate by public signature/version bucket and cap source influence; do not use caller-selected severity as authority.
2. Track report provenance and confidence with explicit unknown/security-suspected classification.
3. Apply retention/deletion to raw sanitized payloads, index entries, derived summaries and backups according to documented limits.
4. Test report poisoning, repeated adversarial reports, classification uncertainty and deletion propagation.

## Acceptance criteria

- A report storm cannot automatically elevate a fabricated defect into release authority.
- Expiry removes indexed/derived payload content within the documented retention window.
- Scoped checks, formatting and configured lint pass; E16 separately records any required deployed/live verification before this behavior is advertised.

## Negative verification

Thousands of duplicates from one reporter request a high-priority code rewrite; bounded triage must not spawn equivalent jobs.

For behavior changes, show the check detects the predicted failure using a disposable isolated test mutation, then restore and report the passing check. Never damage a shared checkout or live environment. A design-only task uses a rejected schema/document fixture instead of pretending it changes runtime behavior.
