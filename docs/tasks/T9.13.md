## Implementation instructions

1. Build a branch name from current/target version and use a stable idempotency key per repository.
2. Generate PR body with changed modules, migration impact, conflicts, tests and compatibility evidence.
3. Use a repository-scoped GitHub installation token; prohibit auto-merge and arbitrary owner-branch overwrite.
4. Test duplicate invocation, closed PR, revoked installation and conflicting branch ownership.
5. Implement the named verification cases at the real changed boundary; run the specified negative case in a disposable fixture, observe its predicted failure, restore the behavior, and record both results.

## Acceptance criteria

- One target upgrade creates at most one active PR and never merges it.
- A permission failure leaves an inspectable local diff and no false success.
- Named scoped checks pass and the specified negative case is demonstrated; live/production qualification remains a separate explicitly authorized E16 gate where applicable.
