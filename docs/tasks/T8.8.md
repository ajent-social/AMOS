## Implementation instructions

1. Require zone, hostname and explicit DNS-only mode for the first qualification of both hosting profiles.
2. Reuse AMSL dnsalias only for DNS-only records; call its rejection boundary for proxied requests.
3. Keep proxy mode disabled until a separate contract covers strict origin TLS, direct-origin bypass, trusted headers, cookies, webhooks and cache bypass.
4. Define DNS ownership checks and fail before modifying records outside the selected zone or app hostname.
5. Implement the named verification cases at the real changed boundary; run the specified negative case in a disposable fixture, observe its predicted failure, restore the behavior, and record both results.

## Acceptance criteria

- DNS-only deployment never claims WAF/CDN protection.
- A proxy configuration cannot be passed to AMSL dnsalias as though it were supported.
- Named scoped checks pass and the specified negative case is demonstrated; live/production qualification remains a separate explicitly authorized E16 gate where applicable.
