# T11.2: Freeze operation-to-tool and policy metadata contract

Status: PLANNED. Detailed draft, not execution-certified. Stage S3; wave 6; owning lane L14; estimate 60 minutes (planning hypothesis).

## Objective

Make mapping deterministic and force explicit policy decisions per operation.

## Dependencies and readiness

Read the actual outputs of every dependency before starting. Reconcile this contract against the frozen contract version and current code; report material mismatch instead of inventing behavior. The listed verification commands are future prescriptions, not claims that executables already exist.

Repository-qualified upstream paths require a separate upstream task claim and that repository's permissions/review rules; they are not permission to edit a neighboring checkout. Shared module files, migration ordering, aggregate APIs, root workflow wiring and executable entrypoints remain integrator-owned unless explicitly listed and exclusively delegated.

## Implementation instructions

1. Specify stable tool names, operation IDs, schema translation limits, descriptions, scope/resource/workspace selection, entitlement and side-effect annotations.
2. Separate protocol hints from enforceable authorization; define deny-by-default exposure and immutable domain-operation identity.
3. Specify nullable/union/map/format handling, size limits and errors for unsupported shapes; do not silently narrow or widen schemas.
4. Add mapping fixtures for permitted exposure, hidden operations, schema errors and missing policy fields.

## Acceptance criteria

- Every exposed fixture contains complete enforceable policy metadata.
- Unsupported shapes and duplicate tool names fail with operation-specific diagnostics.

Use cases: UC-080, UC-081, UC-095.

## Negative verification

An operation with missing tenant selection or entitlement policy must not generate an exposed tool.

For behavior changes, show the check detects the predicted failure using a disposable isolated test mutation, then restore and report the passing check. Never damage a shared checkout or live environment. A design-only task uses a rejected schema/document fixture instead of pretending it changes runtime behavior.
