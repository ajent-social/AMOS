Status: PLANNED. Execution evidence is recorded below; release acceptance remains separate. Stage S2; wave 12; owning lane L09; estimate 60 minutes (planning hypothesis).

## Objective

Make profile choice explicit in generation and immutable during ordinary upgrades.

## Implementation instructions

1. Register managed and small-vm profile capabilities in a lane-owned fragment for root schema integration.
2. Emit only selected profile files and declare current qualification status honestly.
3. Persist the profile identity in environment metadata and detect mismatches with existing state.
4. Return an explicit profile-migration requirement instead of treating a changed profile as resource replacement.
5. Implement the named verification cases at the real changed boundary; run the specified negative case in a disposable fixture, observe its predicted failure, restore the behavior, and record both results.

## Acceptance criteria

- Initializer and plan output display selected profile, resource cost assumptions and qualification state.
- Ordinary upgrade/apply refuses to switch an existing environment profile.
- Named scoped checks pass and the specified negative case is demonstrated; live/production qualification remains a separate explicitly authorized E16 gate where applicable.

## Negative verification

For behavior changes, show the check detects the predicted failure using a disposable isolated test mutation, then restore and report the passing check. Never damage a shared checkout or live environment. A design-only task uses a rejected schema/document fixture instead of pretending it changes runtime behavior.
