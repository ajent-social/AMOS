Repository-qualified upstream paths require a separate upstream task claim and that repository's permissions/review rules; they are not permission to edit a neighboring checkout. Shared module files, migration ordering, aggregate APIs, root workflow wiring and executable entrypoints remain integrator-owned unless explicitly listed and exclusively delegated.

## Implementation instructions

1. Define upstream observer/coder/verifier/builder/release identities and public repository scope independently of owner installations.
2. Translate qualified reproduction into a bounded job referencing only public evidence; never permit upstream jobs to pull owner-private data.
3. Protect release/check/policy files and classify sensitive API/infrastructure changes for elevated review.
4. Test cross-owner job substitution, counterfeit reproduction receipts and attempts to invoke owner maintenance credentials.

## Acceptance criteria

- Upstream job cannot access owner repository, model secret or deployment identity.
- Only qualified reproduction receipts enter the upstream coding queue.
- Scoped checks, formatting and configured lint pass; E16 separately records any required deployed/live verification before this behavior is advertised.
