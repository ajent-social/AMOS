## Implementation instructions

1. Provide preview/status/disable controls showing the exact serialized payload and configured destination without credentials.
2. Queue only sanitized payloads with bounded count/bytes/age, retry backoff and explicit disable/drop semantics.
3. Use a narrow exporter identity and TLS target allowlist; never rehydrate local raw evidence into retries.
4. Test upstream outage, disabled reporting, full disk/spool, destination redirect and retention expiry while app service continues.

## Acceptance criteria

- Disablement prevents future exports and applies the documented queued-item disposition.
- Network retry transmits exactly the previewed sanitized bytes; full queue cannot block request handling.
- Scoped checks, formatting and configured lint pass; E16 separately records any required deployed/live verification before this behavior is advertised.

Use cases: UC-104, UC-111, UC-103.

## Negative verification

A destination redirects to an unapproved host requesting raw evidence; exporter must refuse without uploading anything.

For behavior changes, show the check detects the predicted failure using a disposable isolated test mutation, then restore and report the passing check. Never damage a shared checkout or live environment. A design-only task uses a rejected schema/document fixture instead of pretending it changes runtime behavior.
