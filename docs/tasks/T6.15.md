## Implementation instructions

1. Create minimal independent consumer fixture that disables default renderer and implements shared auth/workspace/billing routes using public exported APIs/contracts.
2. Exercise representative login, MFA challenge, workspace switch, checkout and denied action without AMOS internal imports.
3. Document supported redirect/cookie/CSRF/step-up/asset contracts and page replacement inventory for all shared lifecycle screens.
4. Add consumer compile/import check and browser parity with default flow, including real backend denial despite modified client controls.
5. Format touched Go files with gofmt and changed frontend files with the pinned formatter; run scoped vet/lint and the named behavioral checks, rejecting skipped or zero matching tests.

## Acceptance criteria

- Consumer builds from public AMOS module and imports no internal package.
- Disabled default UI plus custom pages can complete selected lifecycle while backend preserves identical denial.
