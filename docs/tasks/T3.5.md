## Implementation instructions

1. Implement registration with normalized validated input and explicit unverified state; atomically create personal workspace via frozen public transaction seam.
2. Implement password sign-in using generic failure responses, verified-email policy and assurance-aware session minting.
3. Expose OpenAPI fragment operations with limits/idempotency semantics; never create duplicate identity on retry.
4. Write real HTTP registration/sign-in tests asserting status/body, account/workspace durability and wrong-password denial.
5. Format touched Go files with gofmt and changed frontend files with the pinned formatter; run scoped vet/lint and the named behavioral checks, rejecting skipped or zero matching tests.

## Acceptance criteria

- A completed registration yields exactly one person and one personal workspace.
- Unverified or disabled accounts cannot obtain a session with protected-action authority.

Use cases: UC-020, UC-021.
