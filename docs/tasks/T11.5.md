## Implementation instructions

1. Derive owner/resource/scopes/mandatory expiry from current trusted membership and product policy, never request-supplied ceilings.
2. Implement issue/list/revoke/replace service operations over the pinned servicecred store with sanitized DTOs.
3. Define replacement overlap, lost-response revoke/reissue, audit event and idempotency behavior without persisting retrievable bearer secrets.
4. Test actual management HTTP requests for exact status/body, secret reveal once, foreign-key denial and storage failure.

## Acceptance criteria

- Listing and audit records contain no secret or digest; issue reveals the secret only in its successful creation response.
- Requested scopes/expiry outside current authority are rejected; lost response has a documented safe recovery.
- Scoped checks, formatting and configured lint pass; E16 separately records any required deployed/live verification before this behavior is advertised.
