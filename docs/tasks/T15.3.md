## Implementation instructions

1. Test trusted-host/forwarding configuration, TLS assumptions, cookie flags, origin/CSRF validation and safe redirect behavior.
2. Define per-route limits for login, registration, discovery, OAuth, uploads and business API with actionable overload responses.
3. Test body/header/URL size, request timeout, cache leakage and sensitive errors using real HTTP fixtures.
4. Document infrastructure-enforced versus application-enforced controls and attach provider-live requirements to E16.

## Acceptance criteria

- Oversized/host-forged/CSRF-invalid requests fail with documented status and no side effects.
- Anonymous endpoint abuse does not exhaust unbounded durable storage or leak credentials.
- Scoped checks, formatting and configured lint pass; E16 separately records any required deployed/live verification before this behavior is advertised.

Use cases: UC-084, UC-091, UC-112, UC-113.

## Negative verification

Forge forwarded host during OAuth discovery/login callback; issuer/redirect destination remains configured or request fails.

For behavior changes, show the check detects the predicted failure using a disposable isolated test mutation, then restore and report the passing check. Never damage a shared checkout or live environment. A design-only task uses a rejected schema/document fixture instead of pretending it changes runtime behavior.
